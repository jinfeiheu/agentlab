# Agent 安全

## Prompt Injection
Prompt injection 是用户或外部文档在输入中植入指令，试图覆盖系统提示或诱导越权。直接注入来自用户输入，间接注入藏在检索文档、网页或工具结果里。防御要分层：输入检测、最小权限、工具参数校验、输出检查，以及高风险操作的人工确认。

## PII 脱敏
PII 包括邮箱、手机号、身份证号、银行卡号等。日志和 trace 写入前应先用正则或专用库识别并替换，例如把邮箱替换成 `[EMAIL]`、手机号替换成 `[PHONE]`。脱敏不能只做展示层，因为原始内容一旦进入日志或第三方平台就可能无法撤回。测试要覆盖常见格式和边界。

## 工具权限
工具应按风险分级并维护 allowlist。只读检索和计算器风险低；发邮件、下单、删数据风险高，需要额外确认。参数也要校验，例如限制表达式长度、禁止访问任意 URL、检查资源 owner。模型生成的参数一律视为不可信输入，由代码而不是提示词来兜底。

## 人工确认
Human-in-the-loop 是高风险管理的关键控制。LangGraph 的 interrupt 可以暂停图并展示待执行内容，用户确认后用 Command(resume=...) 继续；取消则返回取消结果。确认界面要展示足够信息，不能只显示“是否继续”，否则用户无法判断风险。

## 身份与越权
服务端身份不能由请求体决定。用户登录后由服务端签发 token，API 从 token 解析 user_id，再用它构造 thread_id 和资源命名空间。读取 ticket、记忆等资源时必须校验 owner，跨用户访问返回拒绝。测试要覆盖伪造 token、自选 user_id、相同 session_id 等越权路径。

## 输出安全
输出侧要防止泄露系统提示、密钥和他人数据。可以对敏感模式做过滤，对引用做来源校验，并在回答中避免复述完整的内部配置。安全测试应包含注入样例、PII 样例、越权工具调用和恶意参数，并验证日志中不出现原始敏感值。
